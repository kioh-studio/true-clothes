The Tension Model

A scoring prototype that asks a different question than the current engine. Not “is this outfit decent on every axis?” but “does it have one deliberate idea — and the discipline to keep everything else quiet?” Pick items below and watch both engines disagree.

Build an outfit

The current engine averages its scores, so it rewards outfits that are mild everywhere. The tension model counts axes of contrast and rewards exactly one strong one. Try the default (a tuxedo blazer over a striped tee) — the formality clash is the whole point, yet the old engine punishes it.

Where the two engines disagree

Six archetypal looks, each scored by both engines. Watch the rank flips — the outfits the old engine buries are exactly the ones with a point of view, and its favorites are the forgettable “safe” ones.

Correctness is an average. Taste is a deliberate, single, well-supported deviation — one strong idea, stated once, with everything else kept quiet.

What this prototype models — four contrast axes the live DB already has data for: proportion (fit volume), formality, colour (neutral base vs. pops), texture. Each is scored calm / present / strong / noise. The tension model rewards exactly one strong with the rest calm; it penalises zero (forgettable) and three-plus (costume).

What it deliberately doesn’t model yet — fit-on-body proportion (needs height + torso + garment length), mood/“same-world” coherence, and the styling layer (tuck, roll, cuff). Those are the next levers. The “quiet uniform” card below is the honest edge case: it reads as Safe here because its real taste lives in fit precision, which neither engine can currently see.

Wired against the existing pipeline this slots into ranking.ts as a re-scorer over candidates from generation.ts — no change to filtering or generation.
