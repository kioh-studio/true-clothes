# Data Model: Wardrobe Add-Item Screens

**Feature**: `005-wardrobe-add-item-screens` | **Date**: 2026-06-17

---

## Modified Entity: WardrobeItem (`src/types/fitEngine.ts`)

Two new optional fields added:

| Field | Type | Description |
|-------|------|-------------|
| `measurements` | `Record<string, string> \| undefined` | Type-aware key-value pairs. Keys are field names; values include metric unit suffix (e.g. `"54 cm"`). |
| `link` | `string \| undefined` | Optional product URL for the item's origin listing. |

**Type-aware measurement key sets by category**:

| Category | Valid keys |
|----------|-----------|
| `top` | `chest`, `shoulder`, `length`, `sleeve` |
| `bottom` | `waist`, `hip`, `inseam`, `length` |
| `dress` | `chest`, `waist`, `hip`, `length` |
| `outerwear` | `chest`, `shoulder`, `length`, `sleeve` |
| `footwear` | `size`, `insole` |
| `accessory` / `bag` | `width`, `height`, `depth` |
| `headwear` | `circumference` |

Keys outside these sets are permitted (extensible) but not rendered in the default UI.

## New Entity: AddItemMethod (`src/features/wardrobe-add/types.ts`)

```
AddItemMethod = 'item' | 'ai'
```

- `'item'`: single-item on-device flow (free tier)
- `'ai'`: multi-photo AI wizard (premium gate at Analyse step)

---

## New Entity: PhotoEntry (`src/features/wardrobe-add/types.ts`)

A photo added to the AI wizard Upload step.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `string` | Yes | UUID generated client-side; used as the cache key |
| `localUri` | `string` | Yes | Device file URI from expo-image-picker |
| `method` | `'ai' \| 'item'` | Yes | Whether this photo should be AI-extracted or single-item |
| `note` | `string` | No | Optional user-supplied note about the photo |

**Validation**: At least one `PhotoEntry` required before the Analyse step becomes enabled.

---

## New Entity: PhotoAnalysisStatus (`src/features/wardrobe-add/types.ts`)

Per-photo state tracked in the AI wizard `useAIWizard` hook.

```
PhotoAnalysisStatus = 'pending' | 'processing' | 'complete' | 'failed'
```

The hook maintains `Map<photoId, PhotoAnalysisStatus>` and a separate
`Map<photoId, ExtractedItem[]>` for results. Only photos with status `'failed'` or
`'pending'` are included in the Edge Function request on retry.

---

## New Entity: ExtractedItem (`src/features/wardrobe-add/types.ts`)

An item identified from a photo by the AI analysis service.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `string` | Yes | UUID generated by the Edge Function |
| `sourcePhotoId` | `string` | Yes | The `PhotoEntry.id` this item was extracted from |
| `cutoutUri` | `string \| null` | No | URI of the background-removed cutout image (null in MVP) |
| `name` | `string` | Yes | AI-generated name (editable in review) |
| `category` | `WardrobeItem['category']` | Yes | One of the seven category values |
| `color` | `string` | Yes | Named colour string (e.g. `"Beige"`) |
| `material` | `string` | No | Named material (e.g. `"Linen"`) |
| `brand` | `string` | No | Brand name (e.g. `"Zara"`) |
| `link` | `string` | No | Product URL |
| `measurements` | `Record<string, string>` | No | Type-aware measurement pairs |
| `tags` | `string[]` | No | Free-form tag strings (occasion, season) |
| `removed` | `boolean` | Yes | True if the user tapped REMOVE in the review step |

## AI Analysis Service (`src/services/aiAnalysisService.ts`)

### analysePhotos(photos: PhotoEntry[], cache: Map<string, ExtractedItem[] | null>): Promise<AnalysisResult>

Submits only photos not in `cache` (or in cache with `null` — failed). Returns an updated
cache map and a per-photo status array.

```typescript
interface AnalysisResult {
  updatedCache: Map<string, ExtractedItem[] | null>;
  statuses: Array<{ photoId: string; status: 'complete' | 'failed' }>;
}
```

The Supabase client is called via `sb.functions.invoke('analyse-outfit-photos', { body })`.
