# Contract: analyse-outfit-photos Edge Function

**Feature**: `005-wardrobe-add-item-screens` | **Date**: 2026-06-17

**Function path**: `supabase/functions/analyse-outfit-photos/index.ts`
**Runtime**: Deno (Supabase Edge Functions)
**Auth**: Required — function must verify the caller's JWT via `supabase.auth.getUser()`

---

## Purpose

Accepts one or more clothing item photos and returns extracted attribute data per photo.
In MVP the function returns a deterministic stub; in v2 the stub is replaced by a vision
API call without changing the request/response shape.

---

## Request

### Method

`POST` (invoked via `supabase.functions.invoke('analyse-outfit-photos', { body })`)

### Body

```typescript
interface AnalyseRequest {
  photos: Array<{
    id: string;        // PhotoEntry.id — client-generated UUID
    dataUri: string;   // base64 data URI: "data:image/jpeg;base64,..."
    method: 'ai' | 'item';
    note?: string;
  }>;
}
```

**Constraints**:
- `photos.length` must be 1–10 (validated by the function; 422 if outside range).
- Each `dataUri` must be a valid `data:image/...;base64,...` string.
- The function only processes photos submitted in this request. The client is responsible
  for not re-submitting photos whose results are already cached.

---

## Response

### Success — HTTP 200

```typescript
interface AnalyseResponse {
  results: Array<{
    photoId: string;              // mirrors the input photo id
    status: 'complete' | 'failed';
    items?: ExtractedItemDto[];   // present only when status === 'complete'
    error?: string;               // present only when status === 'failed'
  }>;
}

interface ExtractedItemDto {
  id: string;                     // UUID generated by the function
  name: string;                   // e.g. "Beige linen blazer"
  category: 'top' | 'bottom' | 'outerwear' | 'footwear' | 'accessory' | 'dress' | 'headwear';
  color: string;                  // named colour, e.g. "Beige"
  material?: string;              // e.g. "Linen"
  brand?: string;
  link?: string;
  measurements?: Record<string, string>;   // type-aware, e.g. {"chest":"54 cm"}
  tags?: string[];
  cutoutDataUri?: string;         // background-removed image (null in MVP)
}
```

**Partial success**: The function returns HTTP 200 even when some photos fail. Callers must
check `status` per result. A `'failed'` result does not prevent the function from
processing remaining photos.

### Error responses

| HTTP | When |
|------|------|
| 401 | Missing or invalid JWT |
| 422 | Invalid request shape or `photos` array out of range |
| 500 | Unhandled function error |

---

## MVP Stub Behaviour

For each input photo the function:

1. Sleeps 1.5 s (simulates vision API latency).
2. Returns one `ExtractedItemDto` with deterministic attributes:
   - `name`: `"Extracted Item"`
   - `category`: `"top"`
   - `color`: `"Beige"`
   - `material`: `"Cotton"`
   - `measurements`: `{"chest": "52 cm", "shoulder": "44 cm"}`
3. Never returns `status: 'failed'` in MVP (failure path is tested client-side by
   network error simulation).

---

## Retry Contract

The client tracks per-photo status. On retry it submits only photos whose status is
`'pending'` or `'failed'`. The function has no knowledge of prior attempts. The client
must not re-submit photos with `status === 'complete'` regardless of their results.

---

## v2 Upgrade Path

Replace the stub sleep + deterministic return in `index.ts` with a call to the chosen
vision API (e.g. OpenAI Vision, Google Cloud Vision). No client-side changes are required
if the `AnalyseResponse` shape is preserved.
