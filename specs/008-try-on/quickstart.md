# Quickstart & Validation: Try On

How to run and validate the feature end-to-end. Implementation details live in `tasks.md` (generated by `/speckit-tasks`) and the contracts under `contracts/`.

## Prerequisites
- App runs on a device/simulator via Expo (`npm start` / `expo run:ios` | `run:android`). On-device extraction (`expo-item-extract`) requires a custom dev build; otherwise the AI path is used.
- Supabase project linked; edge functions deployed: existing `generate-item-image`, `generate-outfits` (with the pin extension), and the new `evaluate-item`.
- A test user with: at least some body measurements, a color palette/season, selected styles, and several wardrobe items spanning top/bottom/footwear (so Mix & Match can complete outfits).

## Deploy backend (Supabase CLI — preferred over MCP inline deploy)
```bash
supabase functions deploy evaluate-item
supabase functions deploy generate-outfits   # redeploy with pin_item support
```

## Validation scenarios (map to spec acceptance criteria)

### US1 — Scan → Verdict (P1)
1. Menu → "Try on before you buy" → capture or pick a clear single-garment photo.
2. Expect a progress state, then a Scan Result screen with the **background-removed** item image and extracted attributes.
3. Expect a **Verdict**: overall 0–100 score, a recommendation label, and five criterion rows (Color, Style, Fit, Measurement, Fabric), each with a plain-language explanation.
4. Force a missing-data case: clear the user's measurements → re-scan → Measurement (and Fit) rows show **"Not enough info"** and are excluded from the overall score; the verdict still renders. (FR-009a)
5. Use a photo where fabric isn't determinable → Fabric row shows "Not enough info", excluded. (FR-009b)
6. Confirm nothing is added to the wardrobe at this point. (FR-013 / SC-004)

### US2 — Mix & Match (P2)
1. From the result, tap "Mix & match with closet".
2. Expect a Home-style vertical swipe feed; **every** outfit contains the scanned item, paired only with owned wardrobe items, and each is a complete outfit. (FR-011/FR-012/FR-012a, SC-003)
3. Empty/sparse wardrobe (or no completable outfit) → a clear "nothing to pair yet" state, not broken outfits. (Edge Cases)
4. Back → returns to result; item still not saved. (FR-013)

### US3 — Decide (P3)
1. Tap **Add** → item appears in the wardrobe with its attributes and isolated image; it is usable in normal outfit suggestions afterward. (FR-014/FR-016)
2. Scan another item, tap **No** → nothing saved, temp image cleaned up, return to scan screen. (FR-015, R7)

## Automated checks
- **Unit (Jest)** `src/**/__tests__/`: `tryOnService` response→`Verdict` mapping (incl. unavailable criteria & renormalized composite); `tryOnStore` reset clears state & deletes temp file; recommendation-band mapping.
- **Deno**: `evaluate-item` scoring — deterministic outputs; criterion exclusion when item attr OR profile data missing; Fit/Measurement weighting; engine-primitive reuse (no duplicated math). `generate-outfits` pin path — every outfit contains the pin; absent `pin_item` is a no-op (regression guard); sparse wardrobe → `[]`.
- **Manual**: SC-001 (scan→verdict < 30s on a typical photo).

## Expected outcomes (success criteria)
- SC-001 ≤ 30s scan→verdict; SC-002 ≥ 90% clean scans need no retake; SC-003 100% of Mix & Match outfits include the item; SC-004 0% premature saves; SC-005 100% unknowns shown as "Not enough info" (never fabricated).
